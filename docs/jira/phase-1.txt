h2. a) Architecture decision

||Option||Needs on TV||Needs on PC||Works with Referer-locked streams||Remote control quality||Effort||Risk||
|R1 TV-browser receiver|Internet app open on the server page|Server: HTTP page, WebSocket, proxy|Yes, every request goes through the proxy|Good: play/pause/seek/stop/volume over WebSocket, plus D-pad on the TV|M|Old Chromium on the TV may lack MSE or codecs; user must open a URL once|
|R2 DLNA push|Nothing to open; built-in renderer|Server: SSDP, UPnP controller, proxy|Yes for MP4; HLS only if the renderer fetches playlists (many do not)|Fair: AVTransport state polling, seek support varies by firmware|L|Renderer may reject HLS, MIME types and DIDL metadata are firmware-specific|
|Hybrid (R1 default, R2 fallback)|Either|Both stacks behind one receiver interface|Yes|Best available per stream|L|Two code paths to test on one TV|

*Recommendation: R1 for MVP.* It is the only mode where HLS is under our control (hls.js) and control latency is one WebSocket hop.
R2 moves to v1.1 as a second implementation of the same receiver interface, which gives the hybrid without rework.
The R1 risk (old Tizen Chromium) is retired first by spike CAST-001.

h3. Components

* Extension (MV3): content script (video + DRM detection, all frames) -> service worker (network observation, candidate store in chrome.storage.session) -> popup (pairing, cast, controls).
* Extension <-> Server: HTTP on http://127.0.0.1:8787/api, called from the popup. No sockets held by the service worker.
* Server (Node.js, single process): local API, pairing registry, stream proxy with HLS playlist rewriting, receiver page host, WebSocket endpoint /tv.
* Server <-> TV: HTTP for the page and media (http://<PC-IP>:8787), WebSocket ws://<PC-IP>:8787/tv for pairing and control.
* Server -> origin servers: HTTPS/HTTP with the original page's Referer, Origin, Cookie and User-Agent.

h3. Message contracts (version field v=1 on all)

||Name||Direction||Purpose||
|GET /api/state|Extension -> Server|Server version, receiver URLs, pairing, cast and playback state|
|POST /api/pair|Extension -> Server|Submit the code shown on the TV, receive a session token|
|POST /api/cast|Extension -> Server|Register a stream and its headers, start playback|
|POST /api/control|Extension -> Server|play, pause, seek, stop, volume|
|POST /api/unpair|Extension -> Server|End the session|
|tv.hello|TV -> Server|Receiver connected; says whether it still holds media|

|media.load|Server -> TV|Proxy path, kind, title, start position|

|session.end|Server -> TV|Session ended; show a new code|

h2. e) User journeys

h3. First-time setup
# Install the server on the PC and start it; allow it through the firewall on private networks.
# Load the extension in the browser.
# Open the extension popup: it shows the address to open on the TV.
# On the TV, open the Internet app and enter that address; bookmark it. The TV shows a 6-digit code.
# Type the code into the popup. The TV shows "Connected".

h3. Everyday cast
# Open the TV bookmark (the session is restored if the server is still running).
# Start a video on the PC, open the popup, press Cast on the detected stream.
# The video plays on the TV; the popup shows play/pause, seek, volume and stop.

h3. Failure and recovery
# DRM site: the popup says the video is protected and cannot be cast.
# Server not running: the popup says so and offers Retry.
# Wi-Fi drop: the TV reconnects on its own and keeps the session; if the page was reloaded, playback resumes from the last position.
# Expired link: the popup says the link expired; reload the page and cast again.

h2. f) Assumptions and open questions

* Server is Node.js for MVP and is run from source; a single binary comes with CAST-026. (assumed)
* Extension-to-server transport is HTTP on 127.0.0.1:8787. (assumed, pending CAST-002)
* Pairing code is 6 digits, valid 5 minutes, single use; 5 failed attempts per minute. (assumed)
* One sender per TV; a paired TV shows no code, so a second sender cannot join. (assumed)
* Volume control in R1 changes the video element volume, not the TV system volume. (assumed)
* Cookies are replayed only to the host of the registered stream. (assumed)
